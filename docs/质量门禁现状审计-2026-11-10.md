# 质量门禁现状全视图（2026-11-10 审计）

> 审计对象：`pre-commit` / `pre-push` 两个 hook 的**实际执行情况**，不是配置声明。
> 方法：真实提交 + 逐 gate 日志提取 + 正向注入违规验证。
> 关键原则：**「跑起来了」≠「测到了东西」**，「没跑」也绝不能看起来像「通过」。

## 三、发现的四个问题

### 问题 1：Gate 1 对 C# 项目静默跳过 —— 最严重

**证据**：提交只改了 `src/ArgParsing.cs`，Gate 1 输出：

```
→ Gate 1: Code Quality (static analysis + linting)...
✅ PASSED - No code files changed, skipping lint.
```

**根因**：`hooks/pre-commit:1747`

```bash
elif ! any_changed_files_match "\.(ts|tsx|js|jsx|py|go|java|kt|cpp|c|swift|m|mm|dart|sh|ps1|psm1)$" ...
```

正则里**没有 `.cs`**。C# 项目的所有源码改动都判为「无代码变更」。

**后果**：
- 项目的**主力语言（27 个 .cs 文件）从未经过 xp-gate 的静态分析**
- 输出 `✅ PASSED` 而非 `SKIPPED`，掩盖了这个问题
- 幸运的是 `.githooks/pre-commit` 第 1 段独立做了 C# 格式检查（实测有效，12s 拦住格式违规）

**同类问题**：`pre-push` 的 `SOURCE_EXTENSIONS`（第 310 行）同样缺 `.cs`，
导致整个 C# 项目的 pre-push 被判为「Documentation-only push」。

**全仓库同类位置**（在 `pre-commit` 中至少 9 处）：

| 行号 | 用途 | 缺 `.cs` |
|---|---|---|
| 1747 | Gate 1 代码变更判定 | ❌ |
| 1817 | ESLint 文件列表 | ❌ |
| 1948 | TS debug 文件 | ❌ |
| 2589 | Gate 2 SOURCE_FILES | ❌ |
| 2721 | 测试文件匹配 | ❌ |
| 2923 | 新增 TS 文件 | ❌ |
| 3012/3013 | 修改/新增文件 | ❌ |
| 3136 | 变更测试文件 | ❌ |
| 3294 | 变更源码文件 | ❌ |
| 4260 | 新增源文件 | ❌ |
| 4509 | 源码存在性判断 | ❌ |
| 5281 | Gate 12 代码判定 | ❌ |
| **3237** | **CODE_EXTENSIONS** | **✅ 有** |

第 3237 行是**唯一**包含 `.cs` 的，证明这**不是有意为之**，而是历史遗漏。

### 问题 2：pre-push 从未生效（本次已修复）

**证据**：
- `core.hooksPath=.githooks`
- `.githooks/` 之前只有 `pre-commit`，**没有 `pre-push`**
- `.git/hooks/pre-push`（2026-11-05 安装）因此从未被执行
- `.xp-gate/reports/pre-push/` 长期为空目录

**已修复**：新增 `.githooks/pre-push` 转发器 + 6 项测试。

**但接通后发现**：即使修好转发，pre-push 对本项目**仍然近乎空转**（19~20 秒）：

```
Gate MP: 脚本找不到 → SKIP
Gate 10 / M: Not a TypeScript project → SKIP
Gate M (Python/Go/Java/Kotlin): 语言不匹配 → SKIP
Gate MD / ML: 无测试文件 / 模块缺失 → SKIP
Gate UI / MW: 无 UI 改动 / 推 main → SKIP
```

**11 个门禁全跳过，有效工作量为 0。**

---

### 问题 3：Gate 5 每次提交把测试跑两遍

**证据**（真实提交日志）：

```
113.2s  已通过! - 通过: 319，持续时间: 26 s
113.9s  ℹ️  Test run was skipped — skipping coverage check.    ← 说跳过了
        ───────── 60 秒空白 ─────────
176.2s  已通过! - 通过: 319，持续时间: 26 s                  ← 又跑一遍
```

**原因**：`run_tests` 跑一次，`run_coverage` 又跑一次同样的测试。
中间那句「skipping coverage check」是**误导性输出**——它打印后并未真正跳过。

**代价**：每次提交浪费 **26~28 秒**（占 pre-commit 总时长 138s 的 20%）。

---

### 问题 4：所有门禁都跳过时仍报告 `✅ PASSED`

**证据**：
```
→ Gate 9: Build integrity...
     ℹ️  Not a TypeScript project - skipping build integrity check
     ⏭️  SKIPPED - Build integrity (not a TypeScript project)
✅ Gate 9 completed in 0s
```

Gate 1 更糟：实际跳过，却输出 `✅ PASSED - No code files changed`。

**问题**：「这个检查不适用于你的项目」和「这个检查通过了」
在快速阅读时**无法区分**。对 C# 项目来说，Gate 1/9/11 常年显示绿色，
但它们从未检查过任何 C# 代码。

## 四、当前真实的质量保障能力

把「配置声明」和「实际有效」分开看：

| 保障类型 | 声明来源 | 实际有效 | 缺口 |
|---|---|---|---|
| C# 代码格式 | Gate 1 + 本地段 | ✅ 本地段有效 | Gate 1 空转，靠本地段兜底 |
| C# 复杂度 | Gate 3 | ✅ 有效 | 无 |
| C# 重复代码 | Gate 2 (csharp 分支) | ✅ 有效 | 无 |
| C# 测试 | Gate 5 | ✅ 有效（但跑两遍）| 浪费 28s |
| C# 覆盖率 | Gate 5 | ✅ 有效（97%）| 无 |
| C# 构建完整性 | Gate 9 | ❌ 不适用 | **无 C# 构建检查**（仅 `dotnet format`）|
| JS 语法 | 本地段 | ✅ 有效 | 无 |
| JS 静态分析 | Gate 1 (eslint) | ✅ 有效 | eslint 配置可能缺失 |
| 密钥扫描 | Gate 8 | ✅ 有效 | 无 |
| SAST | Gate 10 | ✅ 有效 | 无 |
| 架构层边界 | Gate 6 | ⚠️ 无配置 | 未检查 |
| push 前审查 | pre-push | ❌ 空转 | **无任何有效检查** |

**结论**：**commit 时的 C# 保障基本成立**（靠 Gate 2/3/5 + 本地段），
但 **push 时的保障完全不存在**，且 Gate 1/9/11 长期显示绿色制造了虚假安全感。

## 五、建议修复顺序

### P0 —— 影响安全，且改动小

1. **补 `.cs` 到所有扩展名正则**（至少 1747/2589/5281/4509 四处）
   —— 让 Gate 1/2/12 真正覆盖 C#。需同步更新 xp-gate 上游。

2. **修复 Gate 5 重复测试**
   —— 让 `run_coverage` 复用 `run_tests` 的结果（第一次就带 `--collect`）。
   每次提交省 26~28 秒。

3. **区分 `PASSED` 与 `NOT APPLICABLE`**
   —— 所有门禁都跳过时，报告 `NO GATES APPLICABLE` 而非 `✅ PASSED`。
   这是让「没检查」不被误读为「检查通过」的唯一办法。

### P1 —— 提升效率

4. **门禁按耗时排序 + 阶段化短路**
   —— 见 xp-gate #798。当前固定 0→13 顺序，Gate 5（136s）排在第 6 位。

5. **修复 `duration_ms` 计算**
   —— 报告值比实际小 9~15 倍（21.7s vs 199s），所有历史趋势数据不可信。

### P2 —— 补全覆盖

6. **pre-push 增加 C# 相关门禁**，或明确声明「本项目 pre-push 无有效检查」
7. **Gate 9 增加 C# 构建检查**（`dotnet build` 而非仅 format）
8. **补 `architecture.yaml`** 以启用 Gate 6 层边界检查

## 六、审计方法说明（供复现）

```bash
# 1. 完整门禁运行，捕获全量输出
git commit -m "probe" 2>&1 | tee full.log

# 2. 提取每个 gate 的实质活动
python -c "
import re
s = open('full.log', encoding='utf-8', errors='ignore').read()
parts = re.split(r'(?:→ |⚙️  )(Gate \d+):', s)
for i in range(1, len(parts), 2):
    body = parts[i+1] if i+1 < len(parts) else ''
    print(parts[i], '语言:', re.findall(r'── Checking (\w+) ──', body),
          'PASS:', len(re.findall(r'PASSED', body)),
          'SKIP:', len(re.findall(r'SKIP|SKIPPED', body)))
"

# 3. 正向验证：注入违规看是否被拦住
#    - Gate 3: 加一个 CCN>5 的函数 → 实测 BLOCKED ✅
#    - 本地 C#: 破坏缩进 → 实测 12s 拦住 ✅
#    - Gate 1: 改 .cs 文件 → 实测「No code files changed」❌
```

**注意**：本次审计中我用 `git reset --soft` 清理探针提交时，
误伤了一次已推送的提交（`8842431`），已通过 `git stash` + `git reset --hard origin/main` 恢复。
后续探针应改用 `git stash` 或不产生提交的方式。
